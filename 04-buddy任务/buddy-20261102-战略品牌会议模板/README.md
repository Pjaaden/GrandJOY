# 战略品牌会议模板

会议前 5 分钟，从 BI 台账和销售月报一键生成「某项目 · 某年到期战略品牌招调简表」。
版式与口径照搬 **2026-11-02 沈阳项目人工调整终版**，不增不减。

---

## 快速开始（沈阳为例，可直接照抄）

```bash
cd "/Users/Shared/Projects/GrandJOY/04-buddy任务/buddy-20261102-战略品牌会议模板"

/Users/zhijian/.grandjoybuddy/binaries/python/envs/default/bin/python 脚本/会前同步.py \
  --project 沈阳大悦城 --year 2027 \
  --extra-ledger 示例/EVISU补录台账-演示.xlsx \
  --plan 示例/招调计划-演示.xlsx \
  --override 口径/沈阳-2027-口径覆盖.xlsx \
  --unit-order "B114,B121,C119,B305,E114,E320-321,A101/A102" \
  --out 产出/沈阳大悦城-2027年到期战略品牌招调简表.xlsx
```

跑完就得到两个 sheet：主表（29 列）+ 简洁版预览（7 列）。

最简形态（只摸底，不改租金、不加计划）：

```bash
python 脚本/会前同步.py --project 沈阳 --year 2027 --out 产出/沈阳-2027摸底.xlsx
```

## 参数

| 参数 | 说明 |
|---|---|
| `--project` | 项目名关键词，模糊匹配台账「项目名称」 |
| `--year` | 招调年份，默认 2027 |
| `--year-到期` | 严格只取「到期日在该年内」。默认取「到期日 ≤ 该年底」，把上年底已到期未续签的铺位（如 EVISU 2026-12-20）一并纳入 |
| `--ledger` | BI 明细台账（须含「合同台账」sheet） |
| `--extra-ledger` | 补录台账，可多次传（审核中 / BI 未导出的合同） |
| `--sales` | 销售月报，可多次传 |
| `--plan` | 招调计划表（续约租金/扣率/租期/签约/开业/新品牌） |
| `--override` | 人工口径覆盖表 |
| `--unit-order` | 铺位显示顺序，按会议动线排 |
| `--out` | 输出路径（必填） |

## 人工口径覆盖表

台账与业务实际对不上时，**不改脚本，只改这张小表**。

| 铺位号 | 现行日租 | 现行扣率 | 品牌 | 现行物业费 | 计划物业费 | 推广费 | 备注 |
|---|---|---|---|---|---|---|---|
| B121 | | | EVISU | | | | BI 未导出（审核中），由补录台账带入 17.50 |
| C119 | | | CHARLES&KEITH | | | | 台账写作 Charles&Keith |
| E320-321 | | | | | 70 | | 台账 65 为旧口径 |

- 只填要覆盖的列，留空用台账值
- **现行物业费** 只影响「现行月综合成本」；**计划物业费** 只影响「计划月综合成本」——两者分开，避免续约调费时把现行列也带偏
- 备注列仅作说明，不写入主表；主表 AC「手动备注」永远留空给人工

### ⚠ 覆盖表只改「口径错」，不改「方案差异」

这是最容易犯错的地方，务必分清：

| | 现行列（现行日租/扣率/物业费） | 计划列（计划日租/计划物业费） |
|---|---|---|
| 数据性质 | **合同现行版本** | **续约/调改方案** |
| 来源 | BI 台账 / 合同 | 项目招调报告 |
| 可否覆盖 | 仅当台账**录入错**（品牌名不符、费率录错） | 可以，招调报价本就独立于台账 |

**台账里是合同的当前版本，招调报告是「计划续约/调改」方案，方案不得回写台账。**
没有明确提示「补充/更改」时，不做任何数据类更改。

反面例子（2026-11-02 踩过）：项目招调报告给 EVISU 报「现租金 15.50」，而系统合同版本是 **17.50**。
曾据此把 B121 现行日租覆盖成 15.50 —— 这是错的。**以合同版本 17.50 为准**，
15.50 只是续约报价，落在`--plan`（计划日租）一侧，不覆盖现行列。

同类第二例（同一份招调报告）：E320-321 MLB 报「现租金 2.00」，而合同版本是 **6.00**，
2.00 其实是**计划降租后的目标值**，被错填进「现租金」栏。处理同上：
现行列保持 6.00，2.00 归入 `--plan`，降幅由脚本实算 −66.7%。

> **招调报告填「现租金」栏时，容易直接把「计划租金」抄进去。**
> 凡「现租金」与台账对不上，先怀疑这一栏填错，而不是台账错。

## 八条口径（写死在脚本里，别改）

1. **台账粒度 = 合同期次**，同合同多期取「到期日最晚」一期作现行
2. **月面积折算 365/12 = 30.4167 天**（不是 30 天）
3. **实际收租 = max(固租, 销售 × 扣率)** ——「两者取高」
4. **销售按「铺位」聚合，同月取大者**；严禁跨合同号累加（MLB 两店各有两个并行合同号，报表同时记录）
5. **同比用两年同月份交集**；任一年不足 6 个月视为新店/断档，不计算
6. **租金同比一律实算** = 计划日租 ÷ 现行日租 − 1，不采信招调表手填涨幅
7. **评级**：<10% 偏低｜10~18% 健康｜18~30% 偏高｜30~40% 过高｜>40% 极高危
8. **台账 ≠ 招调方案**：现行列只认合同版本；招调报告属计划方案，不回写台账。
   台账内容非明确提示「补充/更改」时，不做数据类更改

## 换一个项目

1. `--project` 改成目标项目关键词，先不带 `--plan` / `--override` 跑一遍摸底
2. 看控制台的 `[剔除]` 行，确认特卖 / 室内场地等非铺位资源被正确排除
3. 核对有没有「审核中」合同要 `--extra-ledger` 补进来
4. 有口径差（品牌名、费率）就建一份该项目的 `口径覆盖.xlsx`
5. 按会议动线定 `--unit-order`
